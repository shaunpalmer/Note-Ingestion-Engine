## 3. Architecture Decisions Implemented

### Absolute Paths
All new scripts use absolute paths loaded from `config/paths.conf`. The config file is the single source of truth.

### Pipeline Structure
The ingestion pipeline follows the agreed stage pattern:

```
incoming folder
    |
    v
scan_documents.py (dry-run by default)
    |
    v
process_one_file.py (single file)
    |
    v
Ollama qwen2.5-coder:7b
    |
    v
validate JSON
    |
    v
write .ai.md sidecar
    |
    v
update state/processed-files.json
    |
    v
log everything
```

### State Tracking
Uses SHA256 hashes, not filenames. If a file moves or is renamed, it won't be re-processed.

### Safety Rules Enforced
- Dry-run is the default for all scanners
- `--apply` required to write state or sidecars
- Original files are never modified
- Failed JSON responses are logged, not written
- Empty or unreadable files are skipped with a warning

1. **Add `--quiet` flag to network check**
   Current output is verbose. For cron, a `--quiet` mode that only logs warnings/errors would be cleaner.

2. **Improve risk-level detection in register-scripts.py**
   Currently guesses risk from filenames. Add a `# Risk:` comment parser so script authors can declare their own risk level.

3. **Add JSON schema validation to process_one_file.py**
   Current validation checks required fields manually. Using `jsonschema` would be more robust and easier to extend.

4. **Write the daily report generator**
   The pipeline creates sidecars but doesn't yet write `logs/YYYY-MM-DD-ingestion-report.md`.

### Medium Priority

5. **Add file size limits to process_one_file.py**
   Very large text files could overwhelm Ollama context or take too long. Add a `--max-size` flag.

6. **Add retry logic for Ollama calls**
   If Ollama returns an empty response, retry once with the fallback model before failing.

7. **Add a `--model` override flag to process_one_file.py**
   Allow testing different models per-file without editing config.

8. **Create the Obsidian Inbox folder**
   `/home/mpc/Documents/LinuxBox-Vault/Inbox` doesn't exist yet. Create it when ready.

### Low Priority

9. **Convert Markdown-style YAML frontmatter to real YAML**
   The sidecar currently uses JSON inside triple-dash frontmatter for simplicity. Using `python-frontmatter` or `pyyaml` would produce cleaner output.

## 5. The Warm-Up Script (City Environment)

**Necessity: High**

Without warm-up, the first document in a batch triggers a cold model load (30-60s on CPU, 5-15s on GPU). This causes:
- Timeouts in downstream scripts
- Inconsistent response times
- Potential silent failures if the model pull was interrupted

**Implementation:** `scripts/ollama/warm-ollama-model.sh`

What it does:
1. Check if `ollama` binary exists
2. Check if API is reachable
3. If not, try systemd services, then fall back to `nohup ollama serve &`
4. Wait up to 30 seconds for API
5. Send a tiny prompt with `keep_alive: 3h`
6. If primary model fails, try fallback model
7. Log everything

**Cron schedule:**
```
0 6 * * * /run/media/mpc/Expansion/_System_Snapshot_2026/Documents/LinuxBox-Vault/automation-scripts/scripts/ollama/warm-ollama-model.sh
0 9 * * * /run/media/mpc/Expansion/_System_Snapshot_2026/Documents/LinuxBox-Vault/automation-scripts/scripts/ollama/unload-ollama-model.sh
```
